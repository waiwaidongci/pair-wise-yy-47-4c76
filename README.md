# 企业网站无障碍整改项目管理平台

面向审核员、开发人员、复测员和跨团队负责人的无障碍整改工作台。支持 WCAG 问题录入、同根因合并、复测流转、版本差异、批量分配、草稿恢复和整改报告导出。

## 技术栈

React + Ant Design + Zustand + React Router + TanStack Query + Axios + MSW + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62047`。

核心合并 / 冲突 / 去重逻辑可在无浏览器环境下验证：

```bash
npm run verify:sync
```

## 核心工作流

- 从站点、WCAG 条款、影响范围和证据链接建立问题台账。
- 将同根因问题合并为整改项，并批量指派团队、优先级和截止日期。
- 开发提交修复说明与复测环境，复测员逐项通过、退回或标记不适用。
- 保存常用筛选，比较版本差异，恢复未提交编辑并导出整改报告。

## 可恢复的离线复测批次

复测员带电脑进入网络不稳定的会议室逐项复测，同一问题可能已被开发或另一名复测员同时修改。离线复测批次把复测工作台、问题台账、版本差异和整改报告接到同一套可恢复机制上：

### 断网照常复测，数据留在本机

- 开始批次时冻结当前台账为"上一个确认版本"（含每个字段的字段级版本号基线）。
- 断网时结论、复测环境、证据和备注照常记录，全部持久化在本机（`localStorage`），刷新、关闭浏览器、设备休眠后都可恢复。
- 同一问题重复保存只保留一条本机记录（固定 `recordId` 幂等键），不会出现重复复测记录。
- 顶部与侧边栏实时显示在线/离线状态，可用"模拟断网 / 恢复网络"开关演练；"模拟另一端并发修改"可制造开发或另一名复测员的并发变更。

### 恢复后逐项合并，只提交本人改过的字段

- PATCH 载荷只包含与确认基线相比本人真正改过的字段（状态结论、复测环境、复测证据、复测备注），以及基线版本号。
- 同步按批次固定顺序逐项执行：已同步项跳过不重做，冲突项挂起不阻断后续项，网络等失败立即中断，下次点击"逐项合并剩余项"从第一个未完成项恢复。
- 服务器按 `recordId` 幂等去重，中断重试或重复点击不会产生第二条复测记录。
- 另一端只改了本机未碰的字段（如开发更新根因、修复说明）时自动并入远端版本并在结果中提示。

### 冲突不覆盖，先摆清双方版本

- 状态/根因/复测结论等字段在基线后被双方同时修改时，服务器返回 409 并给出：上一个确认版本（基线）、本机离线记录、另一端最新版本、冲突字段清单、远端变更人与时间。
- 冲突裁决中心要求对每个冲突字段单独选择"保留本机 / 采用远端"，不允许整单覆盖；裁决期间该问题在台账、版本差异、整改报告中继续显示上一个确认版本。
- 全部冲突裁决完成、逐项合并后，三处页面才更新到新确认版本；裁决动作本身记入操作历史。

## 数据模型要点

- `ServerIssue.revision` 为每个受并发保护的字段维护独立 `rev / actor / at`，是"只提交本人字段"与三方冲突检测的基础。
- `OfflineBatch` 持久化批次元信息（会议室、设备、复测人）、纳入问题顺序、确认基线快照、字段版本号与逐项本机记录。
- `OfflineEntry.syncState` 在 `待提交 / 同步失败 / 冲突待裁决 / 已同步` 间流转，驱动可恢复队列与界面冻结。
